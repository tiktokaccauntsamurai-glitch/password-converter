# pwvault — техническое описание проекта

Оффлайн-менеджер переноса паролей между браузерами и печати паролей на бумагу.
Кроссплатформенный (Windows / macOS / Linux), **без единой сторонней
зависимости** — только стандартная библиотека Python 3.9+.

---

## 1. Что он делает

```
   ┌──────────────┐   1. СКАН      ┌───────────┐   3. ЭКСПОРТ   ┌──────────────┐
   │ папка import │ ─────────────► │  память   │ ─────────────► │ папка export │
   │ chrome.csv   │   2. СЛИЯНИЕ   │  Record[] │   4. ПРОВЕРКА  │ apple.csv    │
   │ firefox.csv  │      выбор     │  галочки  │ ◄───────────── │ backup.csv   │
   │ apple.csv    │                └───────────┘   перечитали   │ print_*.html │
   └──────┬───────┘                      │         с диска      └──────────────┘
          │                              │ 5. ПЕЧАТЬ
          │  6. ШРЕДДЕР                  ▼
          │  (только если проверка   A4 / A6 / блокнот 90×170 мм
          └─ прошла на 100 %)        категории, Gmail — отдельно
```

Шесть шагов, и шестой физически невозможен, пока не прошёл четвёртый.
Это главное правило всего проекта.

## 4. Форматы CSV — что и откуда

Проверено по документации вендоров (сентябрь 2026):

| Источник | Заголовок файла | Что требуется при импорте |
|---|---|---|
| **Chrome / Google Password Manager** | `name,url,username,password,note` | обязательны `url`, `username`, `password`; порядок колонок не важен, лишние колонки допускаются |
| **Firefox** (`about:logins`) | `"url","username","password","httpRealm","formActionOrigin","guid","timeCreated","timeLastUsed","timePasswordChanged"` | `url`, `username`, `password` |
| **Apple Passwords** (macOS/iOS) | `Title,URL,Username,Password,Notes,OTPAuth` | ровно эти шесть колонок в этом порядке, UTF-8 без BOM, разделитель запятая, переводы строк CRLF |
| **pwvault backup** | `title,url,username,password,notes,otpauth,category,source_format,source_file` | внутренний формат без потерь |

Источники: [Google](https://support.google.com/chrome/answer/13068232),
[Mozilla](https://support.mozilla.org/en-US/kb/export-login-data-firefox),
[Apple](https://support.apple.com/guide/passwords/export-passwords-mchl35b12625/mac).

### Что теряется при экспорте

Каждый формат в `formats.WRITE_FORMATS` объявляет поле `carried` — список
полей, которые он реально переносит. Отсюда автоматически считается
`lossy_fields`:

| Формат | Теряет |
|---|---|
| Apple | ничего |
| pwvault backup | ничего |
| Chrome | `otpauth` (TOTP-секреты) |
| Firefox | `title`, `notes`, `otpauth` |

Эта декларация используется в трёх местах: в подписи формата в интерфейсе,
в верификации (сравниваются только переносимые поля) и в блокировке шреддера
(удалять источники после только-lossy экспорта программа отказывается).

### Чтение

`formats.read_csv()` определяет диалект по заголовку (`detect_format`),
перебирает кодировки `utf-8-sig → utf-8 → cp1252 → cp1251 → latin-1`,
и складывает всё во внутреннюю модель из шести полей. Незнакомые заголовки
проходят через словарь синонимов `ALIASES` (`login_uri`, `web site`,
`account name`, `login_totp`, …) — этого хватает для Bitwarden, 1Password,
KeePass, Dashlane, LastPass и большинства «просто CSV».

## 5. Слияние дубликатов

Идентичность записи = **(хост без `www`, логин в нижнем регистре)**.
Схема (`https://`), путь, порт, `?query` в ключ не входят — иначе
`https://accounts.google.com/` из Chrome и `https://accounts.google.com` из
Firefox не склеились бы.

Три случая:

1. **Одинаковый пароль в нескольких файлах** → одна запись. Поля берутся
   «богатейшие»: заголовок — первый непустой, URL — самый длинный, заметки —
   объединяются, `source_format` перечисляет все источники.
2. **Разные пароли для одной пары сайт+логин** → *конфликт*. По умолчанию
   остаётся самый длинный пароль, запись помечается жёлтым и флагом `C`.
3. Галочка **«keep every variant of conflicting passwords»** меняет поведение
   на «сохранить все варианты отдельными строками» — ничего не выбрасывается
   молча, вы разбираетесь глазами.

В демо-данных конфликт есть специально: PayPal в Chrome и Firefox с разными
паролями.

## 6. Верификация экспорта — почему именно так

Наивная проверка «мы записали N строк, значит всё хорошо» ловит ноль реальных
проблем: обрыв записи, кривая кодировка, съеденная кавычка, лишний BOM,
переполненный диск — всё это даёт «успешную» запись и битый файл.

Поэтому `vault.verify_export()`:

1. читает **файл с диска заново** тем же парсером, которым читаются чужие
   экспорты;
2. строит `Counter` кортежей по полям, которые формат обязан переносить;
3. сравнивает с `Counter` того, что было отмечено галочкой;
4. `missing` (потерялось) и `extra` (появилось лишнее) должны быть пусты.

URL сравниваются по хосту, потому что писатель Firefox обязан дописать схему
`https://`. Пароли в отчёте о расхождениях заменяются на `<N chars>` — отчёт
безопасно показывать и логировать.

Самотест проверяет и обратное: если обрезать экспортированный файл на две
строки, верификация обязана упасть, а после восстановления — снова пройти.

## 7. Удаление исходников (шреддер)

### Правила допуска

`vault.plan_shred()` возвращает план и список блокеров. **Жёсткие** блокеры не
обходятся ничем:

* в этой сессии нет ни одного успешно проверенного экспорта;
* файл экспорта лежит в той же папке, что и источники (иначе шреддер уничтожил
  бы собственный результат);
* нет загруженных исходных файлов.

**Мягкий** блокер — проверены только lossy-форматы, или часть записей не
отмечена к экспорту и будет потеряна. Его можно принять осознанно: в GUI это
галочка подтверждения + ввод слова `SHRED` + модальное окно с точными числами;
в CLI — `--force --yes`.

### Как именно удаляется

`shred.shred_file()`: три прохода по всему файлу (криптослучайные байты →
`0xFF` → `0x00`), каждый с `flush()` + `os.fsync()`, затем `truncate(0)`, затем
три переименования в случайное 16-символьное имя (чтобы имя файла тоже не
осталось в журнале ФС), затем `os.remove()`.

### Честно о том, чего это не даёт

На SSD перезапись **не гарантирует** уничтожение старых данных: контроллер
из-за wear levelling пишет новый блок, а старый остаётся читаемым
криминалистикой, пока не пройдёт сборка мусора. NIST SP 800-88r1 прямо не
рекомендует программную перезапись как метод санитизации флеш-памяти.

Что реально работает: **полнодисковое шифрование** (BitLocker / FileVault) —
тогда «остатки» это шифротекст без ключа. Программа об этом говорит в
интерфейсе, а не делает вид, что стёрла всё насмерть.

## 8. Модель угроз и что с ней сделано

| # | Угроза | Что сделано | Осталось на вас |
|---|---|---|---|
| **T1** | Утечка паролей по сети из самого процесса | `security.block_network()`: модуль `socket` импортируется первым и обезоруживается (`socket`, `create_connection`, `getaddrinfo`, … заменены на бросающие исключение), затем в `sys.meta_path` ставится блокировщик импорта `ssl/urllib/http/ftplib/smtplib/requests/aiohttp/...`. Проверяется в самотесте | — |
| **T2** | Компрометация через сторонние пакеты | Зависимостей нет вообще. Ставить нечего, обновлять нечего | Целостность самого Python |
| **T3** | Секреты в логах, трейсбеках, core dump | `register_secret()` + `scrub()` подчищают вывод; свой `sys.excepthook` и `unraisablehook`; `RLIMIT_CORE=0` на POSIX; в аудит-лог ключи с именами `password/otpauth/secret/token/pin` пишутся как `<omitted>` | Скриншоты, буфер обмена |
| **T4** | Файлы читаемы другими локальными аккаунтами | `open_private()` создаёт файл сразу с `0600` (не «создали, потом chmod» — без окна гонки); POSIX `umask 0o077`; Windows — `icacls /inheritance:r /grant:r <user>:F` для файлов и `(OI)(CI)F` для папок, при неудаче наследование возвращается, чтобы не запереть файл ни для кого | Права администратора |
| **T5** | Облачная синхронизация утащит плейнтекст | `cloud_sync_warning()` ищет в пути OneDrive, Dropbox, Google Drive, iCloud, Яндекс.Диск, MEGA, pCloud, Box, Nextcloud и показывает жёлтую полосу-предупреждение | Ваш выбор папки |
| **T6** | Файлы «удалены», но восстановимы | Шреддер (раздел 7) | Wear levelling SSD → FDE |
| **T7** | Подглядывание, брошенный экран | Пароли в таблице замаскированы (`**********`), показываются только по явной галочке; авто-очистка памяти после N минут бездействия (по умолчанию 10) | Физическая безопасность |

### Чего программа не может (написано и в интерфейсе, вкладка Security)

* Экспорты браузеров — плейнтекст. Пока файл существует, его читает всё, что
  работает от вашего пользователя.
* Python не умеет надёжно затирать строки в RAM: `str` неизменяем, интерпретатор
  копирует. `clear_memory()` убирает наши ссылки и перезаписывает контейнеры —
  это гигиена, а не гарантия. Radical fix — перезагрузка.
* Своп и гибернация могут вынести плейнтекст на диск. Лечится только FDE.
* Печать оставляет след в очереди принтера. Печатайте на локальный принтер,
  не на сетевой и не на «облачный».

## 9. Печать

### Пресеты

| Ключ | Размер | Поля | Кегль подписей | Кегль пароля | Раскладка |
|---|---|---|---|---|---|
| `a4` | 210 × 297 мм | 10 мм | 7.8 pt | 8.2 pt | таблица `# / сайт+логин / URL / пароль / chk` |
| `a6` | 105 × 148 мм | 6 мм | 6.6 pt | 7.0 pt | узкая: `# / сайт+логин+URL / пароль / chk` |
| `notebook` | **90 × 170 мм** (9 × 17 см) | 5 мм | 6.4 pt | 6.9 pt | узкая |

Размер задаётся через `@page { size: 90mm 170mm }` прямо в файле, поэтому
диалог печати браузера уже открывается с нужной бумагой. Для гарантированно
точного размера есть кнопка **Save exact-size PDF**: она гоняет headless
Chrome/Edge с `--print-to-pdf`, и в PDF получается ровно `255.12 × 481.92 pt`
= 90 × 170 мм (проверено). Дочерний Chrome запускается с отключённой сетью:
`--host-resolver-rules=MAP * ~NOTFOUND`, `--disable-background-networking`,
`--no-pings`, `--incognito`.

### Почему «мелко, но читаемо»

Читаемость при переписывании от руки решает не кегль, а различимость символов:

* пароли — моноширинным шрифтом с перечёркнутым нулём
  (`font-variant-numeric: slashed-zero`, `font-feature-settings: "zero" 1`);
* стек шрифтов `DejaVu Sans Mono → Menlo → Consolas → Liberation Mono` —
  во всех ноль перечёркнут или сужен, а `l` и `1` различимы;
* сверху — «reading guide»: `0/O`, `l/1/I`, `5/S`, `8/B`, `2/Z`, `6/G`, `9/g`, `rn/m`;
* опция «group password in 4s» разбивает пароль неразрывными тонкими
  пробелами по 4 символа (в легенде явно написано, что пробелы — визуальные);
* колонка **Chk** — два символа из алфавита без `0`, `O`, `1`, `I`
  (`sha256(пароль)`, см. `model.password_checksum`). Переписали пароль руками →
  `python -m pwvault --cli --check "то, что набрали"` → сверили две буквы.
  Это детектор опечаток, **не** элемент защиты: он раскрывает ~10 бит, поэтому
  его можно выключить.

### Только английский

Требование «на печати только английский» реализовано двумя разными правилами,
потому что у подписей и у паролей разная цена ошибки (`textutil.py`):

* **Подписи** (заголовок, URL, логин, заметки) — транслитерация: кириллица по
  таблице BGN/PCGN, диакритика снимается через NFKD, остальное → `?`.
  «Яндекс.Почта» станет «Yandeks.Pochta» — и это нормально.
* **Пароли не транслитерируются никогда.** Если пароль — чистый печатаемый
  ASCII, он печатается как есть. Если нет — каждый не-ASCII символ печатается
  как `\uXXXX`, строка помечается `*`, а в легенде появляется фраза
  «decode them, do not type them literally». Транслитерация пароля сделала бы
  бумажную копию бесполезной, а молчаливая замена на `?` — опасной.

Самотест проверяет, что итоговый HTML целиком укладывается в ASCII.

### Категории на бумаге

Порядок секций фиксирован в `categories.CATEGORY_ORDER`, и **GMAIL идёт первым**
— отдельно от остальных сервисов Google. Дальше: GOOGLE, APPLE, MICROSOFT,
EMAIL, FINANCE, SHOPPING, SOCIAL, WORK, DEV, MEDIA, GOV, OTHER.

Правила в `DOMAIN_RULES` — упорядоченный список `(подстрока хоста, категория)`,
первое совпадение выигрывает. Плюс отдельное правило: логин `@gmail.com` на
гугловом хосте → GMAIL. Чтобы добавить свою категорию, достаточно дописать
строку в список и, если нужно, в `CATEGORY_ORDER` / `CATEGORY_LABEL`.

Опция «new page per category» ставит `break-before: page` — удобно, когда
финансовые пароли должны лежать в другом месте, чем всё остальное.

## 10. Две независимые колонки галочек

Требование «выбирать галочками и при печати, и при переносе» реализовано как
**два независимых флага** на записи:

* `selected_export` → колонка **EXP** → попадёт в файлы экспорта и переживёт
  шреддер;
* `selected_print` → колонка **PRN** → попадёт на бумагу.

Они не влияют друг на друга: можно перенести всё, а напечатать только Gmail и
финансы. Кнопки **All / None / Invert** в левой панели действуют **только на
видимые строки** — то есть работают вместе с поиском и фильтром по категориям.
`Space` переключает EXP у выделенных строк, `Shift+Space` — PRN.

Счётчик внизу всегда показывает: сколько всего, сколько отмечено к экспорту,
сколько к печати, сколько сейчас видно.

## 11. Аудит-лог

`export/pwvault_audit.log`, дописывается построчно:

```
2026-09-06T16:52:30 | export | format=apple | file=apple_passwords.csv | records=33 | verified=True | ...
2026-09-06T16:53:02 | shred  | file=chrome_passwords_sample.csv | bytes=1123 | passes=3 | ok=True
```

Пароль туда попасть не может: любое поле, в имени которого есть
`password/otpauth/secret/token/pin`, пишется как `<omitted>`, а всё остальное
проходит через `scrub()`, который вырезает все зарегистрированные секреты.
Самотест отдельно проверяет, что ни один реальный пароль в логе не встречается.

## 12. Самотест

`python selftest.py` разворачивает всё во временной папке (ваши `import/`
и `export/` не трогаются), прогоняет полный цикл вместе с разрушительным шагом
и проверяет 42 утверждения, в том числе:

* сетевой kill switch активен;
* распознаны все четыре диалекта;
* дубликаты слились, конфликт найден;
* **шреддер отказывается работать до экспорта** (и по плану, и по вызову);
* все четыре экспорта верифицированы против диска;
* обрезанный файл экспорта верификацию **не** проходит, восстановленный — проходит;
* частичный экспорт содержит ровно выбранное подмножество;
* все три листа печати — чистый ASCII, размер страницы задан, GMAIL идёт первым;
* кириллический пароль экранирован, а не транслитерирован;
* вложенная папка экспорта распознана как опасная;
* после шреддера источников нет, а файлы экспорта целы;
* в аудит-логе нет паролей.

## 13. Известные ограничения

* Только CSV. Ни `.1pux`, ни KDBX, ни зашифрованные архивы.
* Passkeys не переносятся — их вообще нельзя экспортировать в CSV, это по
  дизайну WebAuthn.
* Разрешение конфликтов — «оставить длинный» или «оставить все варианты»;
  выбора конкретного варианта мышью пока нет.
* Категории определяются по домену, вручную переназначить нельзя.
* Печать идёт через браузер (HTML/PDF), прямой отправки на принтер из
  программы нет — сознательно: так пароль не проходит через ещё один слой
  системных спулеров под нашим управлением, и вы видите превью перед печатью.
* Нет проверки надёжности паролей и повторов — см. `QUESTIONS_AND_IDEAS.md`.

## 14. Как расширять

| Задача | Куда смотреть |
|---|---|
| Новый формат на чтение | `formats.detect_format()` + ветка в `read_csv()`, либо просто пополнить `ALIASES` |
| Новый формат на запись | функция `write_*` + запись в `WRITE_FORMATS` с честным `carried` |
| Новая категория | строка в `categories.DOMAIN_RULES`, при необходимости в `CATEGORY_ORDER` и `CATEGORY_LABEL` |
| Новый размер бумаги | запись в `printing.PRESETS` (ширина, высота, поля, кегли, раскладка) |
| Новое правило безопасности | `security.py`, и обязательно строка в `unmitigated_risks()`, если оно чего-то не покрывает |

После любого изменения — `python selftest.py`.
